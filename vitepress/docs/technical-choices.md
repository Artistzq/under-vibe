# 不是不想选，是连选择题都做不了

你有没有过这种体验：

跟 AI 说了半天想要什么功能，AI 回你一串技术方案——用这个框架、搭那个数据库、鉴权用 JWT、部署上云……你看着这些词，脑子里只有一个想法：

**"这些选项我全都不认识，你让我怎么选？"**

## 一个典型的选择题

假设你想做一个带登录功能的网站。在脑子里你想的是：

> 用户输用户名密码，点登录，就能进到我的页面里。

但到了技术实现层面，你面对的是这样的选择题：

| 问题 | 选项 |
|------|------|
| 用户信息存哪？ | 本地文件 / 数据库 / 云服务（RDS） |
| 密码怎么处理？ | 明文 / 哈希加盐 / OAuth / JWT |
| 登录状态怎么保持？ | Session / Token / Cookie |
| 前端用什么？ | HTML 原生 / Vue / React |
| 部署在哪？ | 本机 / 服务器 / Vercel / 云服务器 |

每一个词你都见过，但每一个你都说不清区别。**你只想做个登录，结果被问到怀疑人生。**

更崩溃的是——你还不敢随便选，因为选错了后面全是坑。可不选又没法往下走。

问题不在于你，而在于：**你脑子里只有功能画面，但技术世界是按"方案"来组织的。**

你想的是"用户点登录进页面"。
技术世界想的是"鉴权方案 + 存储方案 + 会话管理方案 + 前端方案 + 部署方案"。

这两者之间，缺了一层**翻译**。

## 这不是你的问题

你可能会觉得自己"不懂技术"、"基础太差"。

但换个角度想：你知道自己想要什么功能，这说明产品思维没问题。你只是缺少一套**基础知识框架**，来把"我想要的功能"翻译成"技术上有哪些常见方案"。

这种翻译能力，不是靠背名词得来的。而是靠**理解计算机世界里那些不变的基本概念**：

- 数据存哪，取决于你对**数据安全、访问速度、成本**的取舍——这些概念懂了，储存方案自然能选
- 登录怎么做，取决于你**想多方便、想多安全**——懂了这些，鉴权方案不再是黑箱
- 用什么框架，取决于你的**项目规模和维护需求**——懂了这些，框架选择就有依据

## 你需要的是"技术感知"

不是让你学操作系统原理，不是让你啃网络协议，更不是让你手写编译器。

你需要的是**技术感知**——知道计算机世界里有哪些常见零件、它们大概干什么用、什么场景下用哪个。

就像开车不用会造发动机，但你要知道油门刹车方向盘各自的作用。

Under Vibe 要做的，就是帮你建立这种感知。

## 从哪开始？

如果你刚有这个感觉，可以从 **[终端基础](/docs/01-start-project/01-terminal-basics)** 开始——它是你跟计算机对话的第一个工具，也是后续所有操作的基础。

也可以先看看 **[新手引导](/start-here)**，了解整份指南的路线图。

记住那句话：

**（截至目前为止）所有的计算机知识，都是人发明的，都是可以理解的。** 🤓
