# 文件夹隔离：为什么每个项目要独立

AI 对你说：*"把项目放到一个单独的文件夹里，然后 npm install"*

你：*"为什么不能把所有项目放一起？换个文件夹有什么意义？"*

如果你做过几个 AI 编程项目，你可能已经遇到过这种情况：
两个项目都装了 `react`，但它们互相干扰，莫名其妙地报错。

这一篇，我们讲清楚"隔离"这件事——为什么它是避免"在我电脑上能跑，在你电脑上不行"的关键。

## 🎯 实战：看看隔离长什么样

### 两个项目，两套依赖

假设你做了两个项目：

```
~/projects/
├── blog/                    # 博客项目
│   ├── package.json         # 依赖 react 17
│   └── node_modules/        # 装了 react 17
└── dashboard/               # 后台项目
    ├── package.json         # 依赖 react 18
    └── node_modules/        # 装了 react 18
```

每个项目有自己的 `node_modules`，里面装着**它自己需要的版本**。

::: tip 💡 关键点
`blog` 和 `dashboard` 互不干扰。它们各自有各自的 `node_modules`，各自有各自的 `package.json`。

这就是"隔离"。
:::

### 如果不隔离会怎样？

假设你把所有项目放到同一个文件夹：

```
~/all-projects/
├── blog-app.js
├── dashboard-app.js
├── package.json            # 只能有一个！
└── node_modules/           # 只能有一套！
```

问题来了：
- `package.json` 只能写一个 `react` 版本——你选 17 还是 18？
- 两个项目可能有同名的文件，互相覆盖
- 一个项目的配置（比如端口号）可能影响另一个项目

**结果：两个项目都跑不起来，或者跑起来但是各种奇怪的 bug。**

## 🧩 底层揭秘：为什么隔离这么重要？

### 不是"建议"，是"必须"

隔离不是某种高级技巧——它是现代软件开发的基础假设。

当你运行 `npm install` 时，npm 会做一件事：
1. 读取当前目录下的 `package.json`
2. 把依赖下载到当前目录下的 `node_modules`

注意关键词：**"当前目录"**。npm 不关心你电脑上其他项目装了什么，它只关心当前文件夹。

### 一个比喻：出租屋 vs 自己的房间

| 场景 | 对应的项目结构 |
|------|---------------|
| 合租一个房间，所有东西混在一起 | 所有项目共用一个文件夹 |
| 每人有自己的房间，自己的东西自己管 | 每个项目独立的文件夹 |

在合租的房间里，你找不到自己的东西，别人的东西挡路，你换个灯泡可能影响室友。

在自己的房间里，你的东西只有你自己动，出了问题也只影响你自己。

### 隔离的三个层次

隔离不止是"分开文件夹"，它有三个层次：

| 层次 | 隔离什么 | 怎么做 |
|------|---------|--------|
| 文件夹 | 项目文件 | 每个项目一个文件夹 |
| 依赖 | 第三方代码 | 每个项目有自己的 `node_modules` |
| 环境 | 运行配置 | 每个项目有自己的 `.env` 文件（后面会讲） |

::: tip 💡 这个比喻不完全准确，但足够理解
真实项目中，有些工具（比如 pnpm）会在全局共享依赖来节省磁盘空间，但**逻辑上**每个项目仍然是独立的。你不需要关心这个，知道"每个项目是独立的"就够了。
:::

## ⚠️ 常见坑

### 坑 1：在桌面上直接 npm install

```bash
# ❌ 错误：在桌面运行
cd ~/Desktop
npm install
```

npm 在桌面找不到 `package.json`，会报错。
就算你手动创建一个，你的桌面就会变成一个巨大的 `node_modules` 垃圾场。

**正确做法：先在桌面创建一个项目文件夹，然后 cd 进去，再 npm install。**

### 坑 2：把 node_modules 复制给别人

```bash
# ❌ 不要这样
cp -r my-project/node_modules friend-project/node_modules
```

`node_modules` 里可能有平台相关的文件（你在 macOS 上装的包，Windows 上可能用不了）。
而且 `node_modules` 太大了，传起来很慢。

**正确做法：只传 `package.json`，让对方自己 `npm install`。**

### 坑 3：手动改 node_modules 里的文件

"这个 bug 好像是依赖的某个文件有问题，我改一下..."

**千万别。** `node_modules` 是"只读"的——下次 `npm install` 会覆盖你的修改。

正确做法：想办法在你自己项目的代码里绕过去，或者找替代的依赖。

## 🤔 然后呢？

现在你知道了：每个项目独立一个文件夹，是为了让它们互不干扰。

但独立文件夹带来的另一个问题：**你已经做了三四个项目，改了什么东西自己都记不清了。某个版本跑得好好的，改完就坏了，想回到之前的版本，怎么办？**

这就是下一章要讲的内容——**Git：版本管理，后悔药和时光机**。

## 📝 术语表

| 术语 | 意思 |
|-----|------|
| **隔离 (Isolation)** | 让每个项目独立，互不干扰 |
| **node_modules** | 存放项目依赖的文件夹，每个项目有自己的一份 |
| **package.json** | 项目的"购物清单"，记录依赖什么包 |
| **依赖冲突** | 两个项目需要同一个包的不同版本，导致冲突 |
