# 搜索：自己找到答案的能力

AI 对你说：*"这个报错我没见过，你搜一下 `Module not found: Can't resolve 'react'`"*

你：*"搜？去哪搜？搜什么关键词？搜出来一堆结果，哪个是对的？"*

这是每个写代码的人都会遇到的情况——AI 解决不了的问题，你得自己找答案。
好消息是：**搜索答案本身也是一项技能，而且不难学。**

这一篇，我们不讲代码，专门讲"怎么搜"。

## 🎯 实战：从一个报错开始

假设你运行 `npm run dev`，看到这个：

```
ERROR in ./src/App.js
Module not found: Error: Can't resolve 'axios' in '/Users/you/my-project/src'
```

你问 AI，AI 说："装一下 axios 就好了，运行 `npm install axios`"

但装完之后还是报错。AI 又给了几个方案，都不行。

这时候，你得自己搜了。

### 第一步：从报错里提取关键词

报错信息很长，但真正有用的就几个词：

```
Module not found: Error: Can't resolve 'axios' in '/Users/you/my-project/src'
                                    ↑↑↑↑↑
                                   这才是关键
```

提取关键词：**`Module not found` `Can't resolve` `axios`**

不要整段复制。报错里的路径（`/Users/you/...`）跟别人无关，删掉。

### 第二步：选对地方搜

| 去哪搜 | 适合搜什么 | 特点 |
|--------|-----------|------|
| **Google** | 几乎所有问题 | 覆盖面最广，英文结果质量最高 |
| **Stack Overflow** | 具体的技术问题 | 每个问题都有"最佳答案"标记 |
| **GitHub Issues** | 某个库/框架的 bug | 搜库名 + 报错关键词 |
| **官方文档** | 用法、API 参数 | 最权威，但需要你大概知道要找什么 |

::: tip 💡 新手最容易忽略的地方：GitHub Issues
如果你用的库（比如 React、Vite、Tailwind CSS）出了奇怪的问题，去它的 GitHub 仓库，点 Issues，搜你的报错关键词。

很多时候，已经有人遇到同样的问题了，下面就有解决方案。
:::

### 第三步：搜

在 Google 输入：

```
Module not found Can't resolve axios
```

::: tip 💡 一个关键技巧：用英文搜
即使你英文不好，也尽量用英文关键词搜索。

原因很简单：全球程序员都在用英文写报错和解决方案。中文结果可能只有几十条，英文结果有几十万条。

你不需要看懂整篇文章——找到那行命令，复制粘贴就行。
:::

### 第四步：从结果里找答案

搜出来的结果，怎么看？

1. **看标题**：标题里有没有你的报错关键词？
2. **看来源**：Stack Overflow 和 GitHub Issues 优先，个人博客次之
3. **看日期**：超过 5 年的答案，可能已经不适用了
4. **看"已解决"标记**：Stack Overflow 的绿色勾 ✓ 表示这个答案被验证过

### 第五步：试，不行就换

找到可能的答案后，**试一下**。不行？看下一个结果。

不要指望第一个结果就是正确答案。搜索是一个"试错"的过程。

## 🔥 搜索技巧速查

### 技巧 1：加引号精确匹配

```text
# 不带引号：Google 会搜包含这些词的任何结果
Module not found axios

# 带引号：Google 只搜完全匹配这个短语的结果
"Module not found" "Can't resolve" axios
```

### 技巧 2：指定网站

```text
# 只在 Stack Overflow 搜
site:stackoverflow.com "Module not found" axios

# 只在 GitHub 搜
site:github.com axios "Module not found"
```

### 技巧 3：加 `solved` 或 `fix`

```text
Module not found axios solved
Module not found axios fix
```

只搜"解决方案"，不搜"提问"。

### 技巧 4：搜错误码

如果报错里有错误码（比如 `ERR_MODULE_NOT_FOUND`），直接搜它：

```text
ERR_MODULE_NOT_FOUND axios
```

错误码是唯一的，搜出来的结果精准度极高。

## 🧩 底层揭秘：为什么"搜索"这么重要？

### AI 的知识是有边界的

AI 训练数据有截止日期。比如某个库昨天刚发布的新版本有个 bug，AI 不知道。

AI 也看不到这些地方：
- 需要登录才能看的付费文档
- 公司内部的私有知识库
- 刚发布几小时的 GitHub Issue
- 某些被 robots.txt 屏蔽的网站

**遇到这些情况，AI 的答案是"编"的。** 你自己搜出来的才是真答案。

### 搜索能力 = 独立解决问题的能力

在没有 AI 的年代，程序员每天的工作流就是：

```
写代码 → 报错 → 搜 → 找到答案 → 修 → 继续写
```

这不是什么丢人的事——**查资料是编程的一部分。** 没有人能记住所有东西。

现在有了 AI，这个流程变成了：

```
写代码 → 报错 → 问 AI → AI 解决 → 继续写
         ↓（AI 不行）
         搜 → 找到答案 → 修 → 继续写
```

搜索是 AI 的"备用方案"，但备用方案用得好，你就不慌了。

## 🎮 实战练习：你自己搜一次

试试解决这个问题（不管你有没有遇到过）：

**报错信息：**
```
Error: listen EADDRINUSE: address already in use :::3000
```

**任务：**
1. 提取关键词
2. 用 Google 搜索
3. 找到解决方案

<details>
<summary>参考答案（先自己搜，实在找不到再点开）</summary>

**关键词提取：** `EADDRINUSE` `address already in use` `3000`

**搜索：** `EADDRINUSE address already in use 3000`

**常见答案：** 端口 3000 被占用了。要么关掉占用端口的程序，要么换个端口。

**解决：**
```bash
# macOS / Linux：找到占用 3000 端口的进程并杀掉
lsof -i :3000
kill -9 <PID>

# Windows：
netstat -ano | findstr :3000
taskkill /PID <PID> /F
```

</details>

## 🙋 怎么提问（不管是问 AI 还是问人）

搜索不到的时候，就得提问了。但乱问一气，得到的答案也乱七八糟。

### 好的提问包含三要素

| 要素 | 例子 | 为什么重要 |
|------|------|-----------|
| 你做了什么 | "我运行了 `npm install axios`，然后 `npm run dev`" | 让人知道上下文 |
| 你期望什么 | "我期望浏览器打开 localhost:3000 能看到页面" | 让人知道目标 |
| 实际发生了什么 | "终端报错 `Module not found: axios`" | 让人知道问题 |

::: tip 💡 一个模板
```
我在 [什么环境] 下，做了 [什么操作]，
期望 [什么结果]，
但实际 [报错信息/异常现象]。

我已经试过 [什么方法]，但没用。
```
:::

### 问 AI 的时候也一样

❌ 差的提问："我的代码报错了，怎么办？"

✅ 好的提问："我在 Vite + React 项目里 import axios，运行 `npm run dev` 报错 `Module not found: Can't resolve 'axios'`。我已经 `npm install axios` 了，node_modules 里也有 axios，但还是报这个错。怎么办？"

## ⚠️ 常见坑

### 坑 1：直接复制整段报错去搜

报错里有很多跟你环境相关的信息（比如你的文件路径、你的用户名），这些对别人没用。

**正确做法：只提取关键词，路径和用户名删掉。**

### 坑 2：只用中文搜

中文编程社区的内容量远小于英文。很多问题中文搜不到，英文一搜就有。

**正确做法：用英文关键词搜，找到答案后再理解。**

### 坑 3：看到第一个结果就放弃

第一个结果不对，就认为"搜不到"。实际上第 3 个、第 5 个结果可能才是答案。

**正确做法：至少看 5 个结果，都不行再换个关键词搜。**

### 坑 4：搜不到就怀疑自己

"这个问题是不是太蠢了，所以没人问过？"

99% 的情况是：**你搜的关键词不对。** 换个说法再搜。

## 📝 术语表

| 术语 | 意思 |
|-----|------|
| **Stack Overflow** | 全球最大的程序员问答网站，几乎所有编程问题都能在这找到答案 |
| **GitHub Issues** | GitHub 仓库的"问题跟踪区"，可以搜到某个库的已知 bug 和解决方案 |
| **错误码 (Error Code)** | 报错信息里的唯一标识，比如 `EADDRINUSE`、`ERR_MODULE_NOT_FOUND` |
| **关键词提取** | 从一段报错里挑出最关键的几个词，用来搜索 |
