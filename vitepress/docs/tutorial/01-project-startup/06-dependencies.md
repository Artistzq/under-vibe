## 前言

AI 生成的项目运行失败时，终端可能提示找不到模块、版本不兼容，或让你先跑一条安装命令（如 `pip install`）。本篇不再重复介绍运行时和包管理器，而是回答一个更实际的问题：**依赖出了问题时，如何判断项目缺了什么、版本是否正确、安装是否发生在正确的位置**。

> 💡 **场景重现**
>
> AI 对你说："进入项目目录，运行 `pip install` 把依赖装上"
>
> 你："项目明明有代码，为什么还是跑不起来？我该先检查什么？"

::: tip 💡 先记住一句话
**依赖**（Dependency）就是项目运行时需要的外部代码。排查依赖问题时，先确认三件事：**项目有没有依赖清单、依赖有没有安装、安装的版本是否符合要求**。
:::

## 什么是依赖

### 1. 项目不都是从零写的

一个项目几乎不可能每个功能都自己写：发 HTTP 请求、处理日期、解析文件……这些早就有人写好并被验证过了。项目直接"借用"这些现成代码，被借用的代码就是**依赖**。

```text
你的项目代码  →  引用  →  依赖（第三方现成代码）
```

依赖不是某个特定工具的专利。几乎所有技术栈都有"借用现成代码"这件事，只是叫法和工具不同。下面以 Python 的 `pip` 为例，但它背后的机制在各种语言里都一样：

| 技术栈 | 依赖清单 | 依赖目录 |
|--------|---------|---------|
| Python | `requirements.txt` 等 | `venv`（虚拟环境） |
| Java | `pom.xml` | 本地仓库（缓存） |
| Go | `go.mod` | 模块缓存 |
| JavaScript | `package.json` | 依赖目录（如 `node_modules`） |

::: tip 💡 抓住共同点
不管哪种技术栈，套路都一样：**项目有依赖清单 → 工具按清单下载 → 依赖装进项目自己的目录 → 代码引用**。学会一种，其他都能举一反三。
:::

### 2. 先判断：缺依赖，还是环境不对

依赖报错不一定是"没安装"。先把问题分成两类：**环境问题**是运行时或命令本身不可用；**依赖问题**是项目清单要求的代码没有在当前项目中准备好，或版本不符合要求。可以先检查：

1. 当前目录是否是项目根目录：用 `pwd` 或 `Get-Location` 确认
2. 项目是否存在依赖清单：常见文件有 `requirements.txt`、`pom.xml`、`go.mod`、`package.json`
3. 运行时和安装工具是否可用：例如 `python --version`、`java -version`

包管理器（Package Manager）负责读取清单、下载依赖并写入依赖目录；它是排查工具，不是本篇的主题本身。

| 现象 | 优先检查 |
|------|----------|
| `command not found` | 环境或 PATH，不要先重装依赖 |
| 找不到依赖清单 | 当前目录是否正确 |
| `ModuleNotFoundError` / `Cannot find module` | 依赖目录是否存在，是否在项目根目录运行过安装命令 |
| `requires ... version` | 清单要求与当前运行时/依赖版本是否匹配 |

### 3. 依赖目录是什么

依赖目录（Python 里通常是虚拟环境 `venv`）是装进项目的第三方库所在处。它由包管理器自动生成和维护：

- **不要手动改动**：里面是工具管理的文件，改坏了很难修
- **通常不进版本管理**：由清单可以随时重建，没必要提交
- **删掉可重建**：删了重新运行安装命令即可恢复

::: tip 💡 类比
依赖目录像"装好的工具箱"：一次安装一次备齐。清单（依赖清单）在，就能随时重装。
:::

## 实战：亲自安装一次依赖

### macOS / Linux 与 Windows 对照

先创建一个项目目录并进入（用上一篇学过的命令）：

```bash
# macOS / Linux
mkdir my-todo-app
cd my-todo-app

# Windows PowerShell
New-Item -ItemType Directory my-todo-app
Set-Location my-todo-app
```

确认自己确实站在项目目录里：

```bash
# macOS / Linux
pwd
# /Users/yourname/my-todo-app

# Windows PowerShell
Get-Location
# C:\Users\yourname\my-todo-app
```

### 为什么必须在项目目录内安装

安装依赖时，包管理器默认把依赖装到**当前所在目录**的依赖目录里。如果站在错误的位置执行，依赖会装错地方，项目就找不到它们。

```bash
# 错误：没进入项目目录
cd ~
pip install -r requirements.txt   # 依赖装到了主文件夹，而不是项目里

# 正确：先进入项目目录
cd ~/my-todo-app
pip install -r requirements.txt   # 依赖装进 my-todo-app 的依赖目录
```

::: tip 💡 装错位置时的报错
在项目目录外运行安装命令，工具通常会提示"找不到依赖清单"——意思是"当前目录不是项目"。
:::

### 安装前后对比

安装完成后，项目目录里会多出：

| 变化 | 说明 |
|------|------|
| 依赖目录 | 下载好的第三方代码（Python 里是虚拟环境） |
| 锁文件 | 记录实际安装的精确版本，保证大家装的一样 |
| 清单更新 | 新装的依赖被记入依赖清单 |

::: tip 💡 不要担心"文件变多了"
一个项目有几万个小文件很正常，它们几乎都在依赖目录里，由工具管理。真正的项目代码往往就几个文件。
:::

## 原理简析

### 为什么依赖要装进"项目自己的"目录

如果所有项目共用一份依赖，项目 A 用某个库的旧版本、项目 B 用新版本，升级 B 就可能弄坏 A。把依赖装进各自项目的目录后，每个项目自给自足，互不影响——这叫**隔离**（Isolation，即互不干扰）。

| 好处 | 说明 | 类比 |
|------|------|------|
| **文件不混乱** | 项目文件与个人文件、其他项目分开 | 每个房间放一类物品 |
| **依赖可隔离** | 每个项目拥有自己的依赖版本 | 每间房有独立的厨具 |
| **整体可搬运** | 一个项目 = 一个文件夹，可打包、复制、删除 | 一箱物品整体搬走 |
| **多人好协作** | 每个人处理各自的项目目录，互不打扰 | 各干各的工位 |

::: tip 💡 依赖隔离的意义
项目 A 用了某个库的旧版本，项目 B 要用它的新版本。如果所有项目共用一套，升级 B 就可能弄坏 A。隔离后，每个项目在各自的依赖目录里保存自己的那份，互不影响。
:::

### 依赖目录不进版本管理

依赖目录虽然大，但通常不提交到版本管理（Git，后续章节会讲）里：因为它可以由依赖清单随时重建。这就像"清单在，工具随时能重装"，没必要把整套工具箱都带上。

## 避坑指南

### 坑 1：在项目目录外运行安装命令

最典型的错误：随便找个目录就运行安装命令，依赖装错位置。**安装前先 `pwd` 确认当前目录**。

### 坑 2：手动改依赖目录

依赖目录由工具管理，手动改名/删除会导致项目运行异常。要调整依赖，用包管理器（安装、卸载、更新命令），不要手改目录。

### 坑 3：把项目放在带空格的路径

`/Users/yourname/My Project` 这类路径在命令行中需要加引号。项目名建议全小写、用连字符分隔（如 `my-todo-app`），避免空格和大小写带来的麻烦。

### 坑 4：删掉了依赖目录不知道怎么办

依赖目录删掉后，项目会报"找不到依赖"。不用慌：重新运行安装命令即可重建。

::: tip 💡 项目目录和"主文件夹"的区别
主文件夹（`~`）是操作系统给当前用户分配的专属文件夹；项目目录是你为某个项目创建的文件夹。前者是系统级的，后者是项目级的，两者都要知道当前站在哪个。
:::

## 拓展阅读

### 环境与依赖的区别

「环境」一篇讲的"配环境"，重点是语言、运行时、包管理器这三层；而依赖是"项目借用别人的代码"。两者都围绕"让项目跑起来"，配合起来看更容易理解。

### 为什么 AI 老让你"先进项目目录"

理解了依赖装进当前目录这件事，就能明白 AI 为什么反复强调 `cd`：它要保证命令在你真正想操作的那个项目里执行。这也解释了上一篇"为什么命令要在当前目录执行"的意义。

## 术语表

| 术语 | 意思 |
|-----|------|
| **依赖 (Dependency)** | 项目运行时引用的第三方现成代码 |
| **包管理器 (Package Manager)** | 负责下载和管理依赖的程序，如 pip、Maven |
| **依赖清单** | 列出项目需要哪些依赖及版本的说明文件，如 `requirements.txt` |
| **依赖目录** | 项目内存放第三方库的目录，Python 里是虚拟环境 |
| **锁文件** | 记录实际安装的精确版本，保证不同机器装的一致 |
| **隔离 (Isolation)** | 让各项目/各环境的文件与依赖互不影响 |
| **项目目录 (Project Directory)** | 存放一个项目全部文件的独立文件夹 |
| **主文件夹 (Home Directory)** | 操作系统给当前用户分配的专属文件夹，`~` 表示 |
