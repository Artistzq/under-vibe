# 为什么要做这个项目

> VibeCoding 很爽，但这些底层知识能让你走得更远。

## 故事的起点

我是计算机科班出身。AI Agent 火起来以后，写代码、查文档、搭项目都交给 AI，省了很多时间。身边不少朋友没有计算机背景，用 AI 做点简单的事也很顺手。

但一旦做更复杂的事——比如一个带登录和交互的动态网站，或一个复杂数据处理的脚本——就卡住了：

- AI 说"缺少环境变量"，不知道环境变量是什么
- AI 说"执行以下命令可以启动"，不知道执行命令是什么意思
- AI 说"无法搜索"，不知道为什么连不上网，明明浏览器可以上网
- AI 生成了大量垃圾文件，没有隔离和清理的意识

AI 给的代码复制粘贴跑不起来，报错看不懂，只能把错误丢回给 AI，改了再跑还是报错，来回几次就放弃了。问卡在哪，他也说不清楚，只知道"AI 不好用了"。

> 这些东西写过代码的人天天用，却忘了当年自己也是从头学起的。

问题不在 AI，而是缺了一些基本的概念和习惯。模型生成的代码有 bug 看不出来、环境不对不知道怎么排查、文件多了不敢改、AI 给了方案不知道选哪个——背后是同一个问题：**缺少对计算机体系的了解**。

## 为什么没人教

正统学法从数据结构、操作系统、计算机网络一路学到编译原理，需要数学基础、大量时间，大部分内容写代码时根本用不上。但有些东西必须知道：文件怎么组织、程序怎么跑起来、网络请求是怎么回事、Git 是干什么的，还有那些反复出现的术语——缺了它们，和 AI 沟通会特别费力。

这些东西散落在各个课程里，**没有一本是专门写给用 AI 写代码的人看的**。

## 这个项目要做什么

不追求覆盖所有知识点，但主要概念和关键环节都能找到：

1. 从终端和文件系统开始——打开电脑就能跟着做的第一步
2. 讲清楚那些"没人解释的词"——依赖、环境、端口
3. Git、网络基础、一点 AI 原理——知道工具怎么协作，数据怎么传输
4. 每条知识围绕一个具体场景——先知道怎么用，再知道为什么

> ✅ 这个项目是什么：那些**写代码的人觉得肯定知道，但没人告诉你**的事。
> ❌ 这个项目不是什么：不是编程入门教程（不教写代码）、不是计算机专业课、不是 AI 教程。

## 读完会怎样

读完不会让你变成程序员，但和 AI 合作时，会少很多"卡住了不知道怎么办"的时刻：知道"打开终端"是什么意思，能看懂项目文件大概干什么，报错时知道往哪个方向查。

**剩下的事，交给 AI。**

## 📖 本章术语

| 术语 | 一句话解释 |
|------|-----------|
| **VibeCoding** | 让 AI 帮你写代码的开发方式，你和 AI 像"搭子"一样协作 |
| **终端（Terminal）** | 用文字输入命令操控电脑的窗口 |
| **环境变量** | 程序运行时读到的全局设置，比如 API Key 就放在这里 |
| **依赖（Dependency）** | 你的项目运行所依赖的别人写好的代码库 |
| **端口（Port）** | 程序对外提供服务时占用的"门牌号" |
| **Git** | 给代码做版本管理的工具，能后悔、能备份 |
