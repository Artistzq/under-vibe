# 学习路径与目录规划（预目录）

> 本文档是 Under Vibe 教程内容的**预目录**，同时承担**进度维护**职责：它提前描述整条学习路径、目标目录结构与每一篇文章的状态。真正的站点目录由 `vitepress/docs/.vitepress/config.mts` 根据**实际存在的文档**动态生成——只写进规划、尚未成文的文章，不会出现在导航里。
>
> 本文档是**给写作者与维护者看的内部规划**，不作为读者的学习入口，因此不出现在站点侧边栏中。

::: tip 💡 给内容创作者（人和 AI 都算）
动笔前先读本文档。文章的路径、标题、一句话定位以这里为准；每完成一篇，把对应条目的状态改为 ✅，并登记进 `config.mts` 侧边栏。项目进度以本文档为准，不另设进度清单。

**这份约定写在哪里**：`AGENTS.md`（团队总约定，"写作或改动内容前必读"一节）、`.opencode/agents/content-writer.md` 与 `site-architect.md`（代理提示词的"动笔前必读"）、`.opencode/agents/quality-assurance.md`（验收项）、`README.md`（贡献指引）、`PROJECT_SPEC.md`（文件职责）都指向本文档，任何代理从任一入口进入项目都会被引导到这里。
:::

## 一、双线结构

课程采用两条同时推进的线：

- **主线**：做真实项目。围绕一条贯穿项目的旅程推进：提出需求 → 创建项目 → 配置环境 → 安装依赖 → 启动项目 → 修改功能 → 浏览器与服务器通信 → 保存数据 → 处理错误 → Git 保存版本 → 部署分享。目标是让读者最终**做出一个项目**。
- **理论线**：按需解释。由主线中的实际问题引出知识（如 `npm install` → 命令、终端、网络、依赖），**不按传统学科顺序孤立展开**。理论必须回答"它解释了主线中的哪个现象"，对应不上的放入 `side-topics` 支线。

每阶段完成后，安排一次 **Build Lab** 手动实验（关掉 AI 亲手做一遍），再进入下一阶段：

```text
理论文章 → 阶段总结 → Build Lab 手动实验 → 进入下一阶段
```

目录顺序体现**学习顺序**，而非学科分类。

## 五、阶段 × 主线映射

每篇理论文章都必须能回答"它解释了主线中的哪个现象"：

| 主线阶段 | 读者看到的现象 | 对应知识（章节） |
|---------|---------------|-----------------|
| 创建项目 | AI 创建很多文件 | 文件系统、项目结构（`01`→`02`） |
| 安装依赖 | AI 执行安装命令 | 包管理器、网络、依赖（`01`） |
| 启动项目 | AI 执行开发命令 | 进程、端口、运行时（`02`） |
| 浏览器访问 | 出现本地网页 | HTTP、客户端、服务端（`03`） |
| 保存数据 | 增加 JSON 或数据库 | 存储、数据结构（`03`） |
| 出现错误 | AI 修改代码 | 错误、状态、调试（`04`） |
| 项目上线 | AI 配置部署 | 构建、服务器、权限（`06`） |
| AI 卡住 | AI 反复尝试 | 搜索、验证、人工接管（`04`） |

## 六、维护约定

1. **目录是动态的**：`config.mts` 侧边栏只登记已实际完成的文章；规划中但未编写的文章只存在于本文档，不创建占位文件。本文档自身也**不进侧边栏**——它是内部规划，不是读者的学习入口。
2. **进度维护在本文档**：每完成一篇文章，把本文档对应条目的状态改为 ✅，并同步更新 `config.mts` 侧边栏。项目进度不再单独维护在 `PROJECT_SPEC.md`。
3. **新文章写作流程**：按本文档的路径与标题写作 → 更新状态 → 登记侧边栏 → 在 `STYLE_GUIDE.md` 规范下自查。
4. **新增主题**：先在本"预目录"中规划（编号、定位、所在阶段），再落笔成文，避免标题先于内容出现。
5. **编号原则**：`NN-` 前缀表示该篇在同一阶段内的学习顺序，移动文章时保持编号与侧边栏一致；`00-roadmap` 与 `side-topics` 不参与阶段编号。
