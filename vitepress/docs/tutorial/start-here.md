# 有想法，但不知道从哪开始？

这可能是 vibecoding 新手最常见的困境。
脑子里有一百个想法，但面对 AI 聊天框，不知道第一句话该说什么。

::: tip 😵 是不是这样的？
- "我想做一个可以记录日常的 App..."
- "然后呢？"
- "然后... 然后我就不知道了"
:::

别担心，这不是你的问题。
这是一个典型的"知识盲区"——没人告诉过你，
**和 AI 合作做项目也是有流程的。**

## 第一步：把想法"压平"

大部分人的想法是这样的：

::: warning ❌ 错误示范
"我想做一个社交 App，用户可以发动态、点赞、评论、关注、私信、建群..."
:::

这是一个"立体"的想法——它包含了太多东西，
别说 AI 了，就是专业产品经理拿到这个也会懵。

你需要把它"压平"，**找到那个最小的、能跑起来的版本。**

::: tip ✅ 正确示范
"我想做一个最简单的留言板：任何人都可以输入文字，提交后显示在页面上。"
:::

看出区别了吗？

- ❌ 描述有**哪些功能**
- ✅ 描述用户**具体做什么**

## 第二步：回答三个问题

在打开 AI 之前，先在纸上写下这三个问题的答案：

### 1. 谁在用？

是给你自己用？还是给某个特定人群用？

👉 越具体越好。"我自己"比"所有用户"好一万倍。

### 2. 他打开这个东西，第一件事做什么？

是看到一个登录页？还是直接看到内容？
他要点击什么？输入什么？

👉 只描述第一步，不要描述第二步之后的事情。

### 3. 做完第一步之后，会发生什么？

点击提交后会怎样？页面显示什么？
数据会保存吗？保存到哪？

👉 只描述直接后果，不要引申。

::: tip 📝 举个完整的例子
**谁在用？** 我自己

**打开后第一件事做什么？** 我看到一个输入框和一个"保存"按钮，我在输入框里写点什么，然后点保存。

**然后会发生什么？** 我写的内容出现在页面上。即使刷新页面也还在。
:::

就这么多。三句话。
这就足够 AI 给你生成一个能跑起来的项目了。

## 第三步：和 AI 的第一句话

现在你可以打开 AI 了。第一句话就这么说：

```
帮我做一个极简的网页笔记工具：

1. 用户打开页面，看到一个大输入框和保存按钮
2. 用户输入内容后点击保存，内容存在浏览器本地
3. 刷新页面，内容还在输入框里

用 React + Tailwind，越简单越好，不要额外功能
```

### 这句话的黄金结构：

| 部分 | 例子 |
|-----|------|
| **一句话描述是什么** | 帮我做一个极简的网页笔记工具 |
| **1/2/3 条用户行为** | 用户打开看到什么 → 做什么 → 得到什么 |
| **技术栈约束** | 用 React + Tailwind |
| **范围约束** | 越简单越好，不要额外功能 |

::: warning ⚠️ 最重要的一条约束
一定要加：**"越简单越好，不要额外功能"**

AI 有一种"热心过度"的倾向，它总喜欢给你加一堆花里胡哨的东西。
这句话可以有效防止它做过头。
:::

## 第四步：跑起来！

AI 给你代码之后，它通常会告诉你怎么运行：

```bash
npm install
npm run dev
```

如果你看不懂这两句话——没关系，
回去看前两章：[终端基础](./01-getting-started/01-terminal) 和
安装依赖。

看完你就懂了。

## 第五步：然后呢？

一旦项目跑起来了，你就进入了"良性循环"：

```
有了一个能用的版本
    ↓
你用了一下，发现"要是能 XX 就好了"
    ↓
跟 AI 说："帮我加一个功能，让它可以 XX"
    ↓
得到更好的版本
    ↓
重复以上过程
```

**最难的永远是第一步——让第一个版本跑起来。**

只要跑起来了，后面的事情就像滚雪球一样，自然而然就发生了。
你会越来越知道该怎么跟 AI 描述需求，
也会越来越懂那些"术语"到底是什么意思。
